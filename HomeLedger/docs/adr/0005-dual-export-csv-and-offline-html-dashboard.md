# ADR-0005: Двойной экспорт отчётов — табличный CSV (Excel) и автономный HTML-дашборд с SVG

## Контекст и постановка задачи

В рамках ЛР № 3 был предусмотрен только экспорт помесячного отчёта в CSV для Excel (`REQ-FUNC-014`). На втором раунде переговоров (ЛР № 4) Заказчик попросил удобный визуальный отчёт с графиками, который можно показать семье или распечатать без установки дополнительного ПО и без доступа к сети Интернет. Как реализовать визуальный отчёт в консольном приложении на чистом C++17?

## Драйверы решения

* CON-1, CON-2: запрет на внешние библиотеки генерации PDF/PNG (libharu, Cairo) и запрет на загрузку JS/CSS-библиотек из Интернета (Chart.js CDN).
* REQ-FUNC-024: наглядная круговая диаграмма расходов, столбчатая динамика за 6 месяцев и интерактивный фильтр операций.
* Ограниченный бюджет и фиксированный дедлайн 8 недель (требование простоты и автономности реализации).

## Рассмотренные варианты

* Генерация растрового BMP/PNG средствами самописного растеризатора на C++.
* Генерация автономного однофайлового HTML5-документа со встроенным CSS, векторной графикой `<svg>` и локальным JavaScript-фильтром.
* Генерация исходника LaTeX / Markdown для внешней конвертации.

## Итог решения

Выбранный вариант: «Автономный однофайловый HTML5-документ со встроенной SVG-графикой», потому что любой современный ПК с Windows или Linux содержит системный браузер, HTML-файл генерируется средствами стандартного `std::ostringstream` без сторонних библиотек, не требует сети Интернет и поддерживает интерактивный поиск по журналу операций.

### Последствия

* Хорошо, потому что пользователь получает профессиональный визуальный дашборд одним файлом `report_ГГГГ-ММ.html`, пригодный для просмотра и печати в PDF из браузера.
* Хорошо, потому что CSV-экспорт сохранён в полном объёме для табличных расчётов в Excel.
* Плохо, потому что при генерации HTML необходимо строго экранировать пользовательские строки (`htmlEscape`) во избежание нарушения разметки или XSS при просмотре.

### Подтверждение

Проверяется в `testStorageBackupAndHtml()` (`tests/tests.cpp`) наличием `<svg>`, данных категорий/целей и корректным экранированием в `htmlEscape`, а также визуальным рендерингом в браузере Edge.

## Плюсы и минусы вариантов

### Самописный растеризатор BMP/PNG

* Хорошо, потому что создаёт статичную картинку.
* Плохо, потому что требует реализации шрифтового рендеринга кириллицы, сглаживания и сжатия zlib/DEFLATE с нуля.

### Автономный HTML5 + SVG

* Хорошо, потому что векторная графика остаётся чёткой при любом масштабе, поддерживает кириллицу и интерактивность за ~180 строк C++.
* Плохо, потому что требует наличия браузера для просмотра (выполнено на всех современных ОС).

### Генерация LaTeX / Markdown

* Хорошо, потому что легко формируется текстом.
* Плохо, потому что требует установки компилятора TeX или просмотрщика у конечного пользователя.

## Дополнительная информация

Связано с требованиями REQ-INT-006, REQ-FUNC-014, REQ-FUNC-024 и проектным представлением `DV-008`.
