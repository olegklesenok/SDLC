# Глоссарий проекта «HomeLedger — Домашняя бухгалтерия»

Настоящий документ определяет единую терминологию предметной области и архитектуры системы «HomeLedger v1.0.0» (ЛР № 5, отдельный файл глоссария).

| Термин | Категория | Определение |
|---|---|---|
| Актёр (`Actor`) | UML / Моделирование | Внешняя сущность (пользователь, роль или системное время), инициирующая варианты использования или получающая информацию от системы |
| Атомарное сохранение | Хранилище | Двухфазная запись данных во временный файл `.tmp` с последующей заменой рабочего файла `rename` для защиты от сбоев |
| Баланс | Предметная область | Суммарный денежный остаток по всем кошелькам с учётом начальных остатков, доходов, расходов и переводов |
| Быстрый ввод | Интерфейс | Однострочная команда главного меню вида `-18,50 прод хлеб` или `+250 подраб сайт`, автоматически распознающая тип, сумму, категорию и комментарий |
| Вариант использования (`Use Case`) | UML / Моделирование | Законченная последовательность транзакций, выполняемая системой в ответ на событие актёра и дающая измеримый результат |
| Группа категории | Предметная область | Классификатор расхода для правила 50/30/20: `Необходимое` (Needs), `Желания` (Wants) или `Сбережения` (Savings) |
| Денежная сумма (`Money`) | Архитектура | Знаковое 64-битное целое число (`long long`), хранящее сумму в целых копейках для исключения погрешностей округления (ADR-0002) |
| Дневной лимит | Аналитика | Расчётная максимальная сумма трат в день до конца месяца, позволяющая отложить целевые 20 % дохода |
| Долг (`Debt`) | Предметная область | Финансовое обязательство между пользователем и контрагентом в одном из двух направлений: «Мне должны» (`OwedToMe`) или «Я должен» (`IOwe`) |
| Индекс финансового здоровья | Аналитика | Композитная оценка бюджета от 0 до 100 баллов из четырёх компонентов: норма сбережений (30), правило 50/30/20 (25), лимиты (25) и подушка безопасности (20) |
| Категория (`Category`) | Предметная область | Классификационный признак операции («Продукты», «Зарплата» и др.), привязанный к типу (доход/расход) и группе 50/30/20 |
| Кошелёк (`Wallet`) | Предметная область | Локальный счёт учёта средств («Наличные», «Карта», «Копилка») с собственным начальным остатком и текущим балансом |
| Лимит (`Budget`) | Предметная область | Месячное ограничение суммы расходов по выбранной категории с порогом предупреждения 80 % («Почти исчерпан») и 100 % («Превышен») |
| Операция (`Operation`) | Предметная область | Атомарная учётная запись с уникальным `id`, датой, типом (`Income`, `Expense`, `Transfer`), суммой, категорией, кошельком и комментарием |
| Отчёт HTML-дашборд | Интерфейс / Экспорт | Автономный однофайловый HTML5-документ с векторными SVG-диаграммами, показателями здоровья и клиентским JS-фильтром операций |
| Перевод (`Transfer`) | Предметная область | Внутреннее перемещение суммы между двумя кошельками пользователя; не изменяет общий баланс и статистику доходов/расходов |
| Пиковый день расходов | Аналитика | День недели с наибольшей суммой расходов за период по данным модуля `weekdayBreakdown` |
| Подушка безопасности | Аналитика | Отношение текущего общего баланса к среднемесячным расходам за последние три месяца, выраженное в месяцах автономной жизни |
| Правило 50/30/20 | Предметная область | Методика распределения чистого дохода: до 50 % на обязательные нужды, до 30 % на желания, не менее 20 % в сбережения |
| Прогноз расходов | Аналитика | Линейная экстраполяция трат на полный календарный месяц исходя из среднедневного расхода с начала месяца |
| Регулярный платёж (`RecurringPayment`) | Предметная область | Шаблон повторяющегося ежемесячного расхода или дохода (аренда, интернет, стипендия) с контролем месяца последнего проведения (`last_ym`) |
| Резервный снимок | Хранилище | Именованная папка копий всех 7 CSV-таблиц в `data/backup/snapshots/` с автоматической ротацией до 10 версий |
| Стек отмены (`Undo`) | Интерфейс | Хранилище до 15 предшествующих снимков состояния `Ledger` в оперативной памяти для мгновенного отката ошибочного действия |
| Финансовая цель (`SavingsGoal`) | Предметная область | Накопительная цель с целевой суммой, текущим прогрессом и датой завершения; пополнение формирует расход в категории «Сбережения» |
| Ядро логики (`ledger_core`) | Архитектура | Статическая библиотека C++17 без зависимостей от консольного ввода-вывода, разделяемая между CLI-приложением, тестами и будущим GUI |
